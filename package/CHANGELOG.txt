FC4Hook changelog
=================

1.12.3
  - Fix: a per-weapon clip made the hands disappear - the clip was never loaded (a resource only loads when
    something loaded depends on it). It's now hung on the game's own clip so it loads, and until it has, the
    game's clip plays instead.

1.12.2
  - Fix: clip names didn't show in Workshop > Animations (the names file was read once, too early, and the
    empty result kept). It's re-read until it has names; the tab shows how many are loaded.

1.12.1
  - Workshop > Animations names the clips: "Reload (2.00 s)", "Shoot (0.67 s)", "Reload (empty, aiming)"... (from
    File log > Find clip names), sorted by name (Sort by name), each clip once.
  - Which weapon is in your hands: weapons given with the Armory / Give it to me are recognised (the slot check
    didn't match). Per-weapon animations need the weapon given that way.

1.12.0
  - Per-weapon animations: Workshop > Animations > "Only for this weapon" (on by default) saves your clip as
    files\fc4hook\clips\<weapon item>_<clip>.ani, and FC4Hook plays it instead of the game's clip only while
    that weapon is in your hands. The weapon you borrowed the animation set from keeps its own clips.
  - The Workshop script publishes the weapon in your hands (state weapon.item / weapon.probe; shown in the
    Animations tab as "Holding").

1.11.1
  - Exported animation .glb: the gun's moving parts (CLIP, SLIDE, HAMMER...) are now bones of the same armature
    as the arms (they were empties), so they pose, key, retarget and bake like every other bone.

1.11.0
  - Animations: weapon clips carry the gun's own animation (its CLIP / magazine, SLIDE, HAMMER... bones). Export
    .glb now includes those parts as extra bones hanging from the right hand (named from the gun's model, e.g.
    CLIP), and Use my .glb writes them back: animate the CLIP bone in Blender and the magazine (or the Ray Gun's
    batteries) moves in game. Reads the short clip header the gun animations use.

1.10.2
  - Workshop > Arms also copies the chosen weapon's reload style (every weapon-properties setting with "reload"
    in its name: magazine vs shell by shell...). Before, a pistol given the 1887's animations still reloaded
    like a pistol. The first version of the properties file is kept as .orig.

1.10.1
  - Workshop > Arms remembers the chosen weapon's models (workshop.txt: animset=, bones=, bones_tp=). New models
    made with Model > Use my .glb are then built on that weapon's bones, so they sit right in the hands with its
    animations.

1.10.0
  - Workshop > Arms: give a weapon another weapon's first-person animation set (how it's held, drawn, reloaded,
    sprinted with). A set is three things in the weapon's item file that must agree: the animation-type number
    (picks the weapon's branch of the move data; 1911 = 4, D50 = 20), the animation package (kimber, deserteagle...)
    and the gun skeleton. The first version of the file is kept as <id>.ark.fcb.orig.
  - FCB files can now be rebuilt with text of a different length (back-references are fixed up).

1.9.4
  - Package add/remove logging (and PackageSwap) works from game start.

1.9.3
  - Snapshot arms only uses weapon clips (not generic no-weapon idles).

1.9.2
  - File log: "Snapshot arms" saves the player's first-person animation state to dumps\arms_snapshot_N.bin
    (research: what makes a weapon use its animation set).

1.9.1
  - File log: "Find files using these clips" also takes id:<hex>,<hex> or num:<decimal> to find every game file
    containing those 8-byte values.

1.9.0
  - dumps\file_log.txt starts fresh each game session (it could grow past 400 MB).
  - [Debug] PackageSwap=from:to in fc4hook.ini: whenever animation package <from> is given to something, <to>
    is given instead (research tool for weapon animation sets).

1.8.9
  - File log: [ClipStart] lines also say where in the animation state the current weapon's name hash sits.

1.8.8
  - File log: [ClipStart] lines: which game code started each animation clip (once per clip and caller).

1.8.7
  - File log: [PackageAdd] / [PackageRemove] lines: every animation package added to or removed from a character,
    with the calling code.

1.8.6
  - File log: [PackageUse] lines record which game code looks up each animation package (e.g. kimber) and from
    where (FC64 call stack), once per caller - for finding how a weapon picks the player's animation set.

1.8.5
  - File log: "Find files using these clips" lists every game file that refers to the clips whose name contains
    the text you type (e.g. sekimber = the 1911's clips), in dumps\clip_refs.txt (files copied to dumps\extracted\refs).

1.8.4
  - File log: "Find clip names" looks for the real names of animation clips (e.g. ..._reload_ak74m.mab): reads every
    game file for animation file names and tries likely ones (each animation folder x each name, weapon swapped for
    every other weapon). Found names go to dumps\clip_names.txt and show up after Label animation clips.

1.8.3
  - File log: Extract on a [CAnimationPackageResource] line (weapon animation sets: kimber, ak74m...) dumps
    the package from memory to dumps\extracted\__unknown\packages\ (packages aren't archive files).

1.8.2
  - Exported animation .glb files remember which clip they came from (the animation is named FC4_<clip id>;
    Blender keeps it). Workshop > Animations: "Use my .glb (finds its clip)" puts a .glb on the right clip by
    itself, so files can be renamed (reload.glb...); a .glb used on the wrong row is refused.
  - One Blender frame = one game frame in exported files (24 fps timeline), so Blender never resamples the
    animation: through a real Blender export the result matches the game's clip to 0.006 degrees (before: up
    to 3.5 degrees off). The clip keeps the game's own speed. Re-export clips exported with 1.8.0/1.8.1.

1.8.1
  - Workshop > Animations: each clip shows its length and which of the weapon's timing stats it most likely
    belongs to ("probably reload (stat 3.90 s)"). A clip runs a little longer than its stat: the stat is when the
    action is done in gameplay, the clip also has the arms settling back (MG42 reload: stat 3.9 s, clip 4.17 s).

1.8.0
  - Custom first-person animations. Workshop > your weapon > Animations: tick Watch, Clear, use the weapon in
    game, and the clips the game played are listed. "Export .glb" turns one into a Blender file (armature + the
    animation, fc4hook\dumps\animations\<id>.glb); edit it, export as glTF Binary, and "Use my .glb" writes it
    into the weapon's mod as a replacement clip. "Restore the game's" removes it.
    Clips are shared by every weapon that uses them (the Ray Gun uses the Kimber's).
  - Developer > Animation > Clip monitor: ".glb" export per clip.
  - The Ubisoft "aNi" clip format is documented in docs/ANI_FORMAT.md (source).

1.7.11
  - Extracting: files listed only in the archives' sub-indexes (e.g. the first-person arms models) can now
    be extracted too.

1.7.10
  - Developer > Animation > Clip monitor: "Extract" per clip and "Extract all listed" (to
    dumps\extracted\animations\<id>.ani), for working on custom animations.

1.7.9
  - Fixed: .glb models were black in first person. The game's "_s"/"_m" weapon textures are packed masks
    (red = shine, green = ambient occlusion, blue = gloss), not plain shine maps; the plain grey FC4Hook
    wrote there put every surface in deep shadow. The mask is now packed like the game's own. Rebuild.

1.7.8
  - Better materials for .glb models: each piece now gets its own colour, normal and specular (shine)
    textures. A normal map or metal/roughness map packed in the .glb is used; without a normal map one is
    made from the colour texture (panel lines and engravings become bumps), and the shine comes from the
    material's roughness and metallic values. Rebuild your models to get it.

1.7.7
  - Workshop > Model: the "On the ground (pickup)" row works now. The pickup's model path is written as
    text inside the pickup archetype (not as a ModelPath), so the row finds it there, builds your .glb on
    it and swaps the path in place.

1.7.6
  - Moving parts for .glb models: name a Blender object after a part of the base weapon (CLIP, SLIDE,
    HAMMER... or MAG / MAGAZINE / BATTERY for the clip) and it goes on that part, so the weapon's own
    animations move it: the magazine comes out on reload, the slide racks. Everything else is the FRAME.
  - Fixed: parts are stored relative to their bones. On weapons whose bones aren't at the origin (the
    Kimber's FRAME sits 7 cm back) the model was shifted by that much. Rebuild your models.

1.7.5
  - Fixed: .glb models looked almost black. Their normals were written x, y, z; the game stores them
    z, y, x, so most surfaces were lit from the wrong side. Press "Use my .glb / .obj" again to rebuild.

1.7.4
  - Third-person models: .glb models now work on models with several LODs (the _tp models other players
    see, and the ones lying on the ground). Workshop > Model now also lists the pickup's model.
  - Scale and Move (cm) next to "Use my .glb / .obj" to fit a model to the weapon without Blender.
  - Fixed: the new model's pieces are now always put on the weapon's FRAME part (before, on some weapons a
    piece could land on the CLIP or SLIDE and move with it), and get materials of their own instead of
    replacing one of the base model's.
  - First-person and third-person conversions of the same .glb no longer overwrite each other.

1.7.3
  - .glb models now work on more base weapons: fixed "the base model has an unsupported layout" (the
    Kimber and others have extra bytes at the end, fewer skin groups, and different data padding).
  - When the base weapon has fewer free pieces than your model has materials, the extra textures are packed
    into one 2x2 texture atlas with the main one instead of being dropped (up to 4 textures).
  - If the base model has no plain material to copy, the Desert Eagle's is used.

1.7.2
  - Fixed: .glb models were invisible. Their materials were copied from the Desert Eagle's glowing-sight
    material (which has no real colour map); they now copy a normal colour + normal-map material.
    Press "Use my .glb / .obj" again to rebuild. Don't move the files it writes: the model refers to
    them by their game path (graphics\fc4hook\<mod>\...).

1.7.1
  - Fixed: a weapon with a .glb model crashed the game when drawn (in the graphics driver). Textures bigger
    than 256x256 are now written the way the game stores them: the top level in a separate _mip0.xbt file.
    Press "Use my .glb / .obj" again to rebuild a model made with 1.7.0. Same fix for Models & Textures >
    Image -> game texture.

1.7.0
  - Completely custom weapon models: F8 > Workshop > your weapon > Model > "Use my .glb / .obj".
    Export your model from Blender as glTF Binary (.glb) with its textures packed in, lined up where the
    base weapon's model sits. FC4Hook builds a new .xbg on the base weapon's skeleton (it moves with the gun
    and keeps its animations), converts the .glb's textures, makes materials for them, saves it all in the
    mod's files\graphics\fc4hook\<mod>\ folder and points the weapon at it. Up to one texture per free
    piece of the base model (the Desert Eagle has 3).
  - First-person models only for now; third-person (_tp) models have several LODs and aren't supported yet.

1.6.4

    Developer (dev mode only; every old Developer sub-tab is its own page), FC4Hook (Console, Settings, About).
  - Models & Textures moved out of Developer, so it no longer needs developer mode.

1.6.3

    normal map or specular, all mip levels), written into a mod at the game path you choose
  - (groundwork for fully custom weapon models: texture and material building)

1.6.2
  - Cheats: "Save the game now" button (the game's own save)
  - Workshop > Model: fixed the gun turning invisible when a full Windows path was typed (the game
    knows files by their GAME path, e.g. graphics\model\gun.xbg). Now any of these work: a game
    path, the full path to an .xbg in a mod's files\ folder, or an .xbg anywhere (copied into the
    mod). Paths that don't exist are refused. Setting a model changes only that slot (first- and
    third-person can't overwrite each other any more). New "Reset to original" button per slot

1.6.1
  - Fixed: a weapon whose model was changed in the Workshop showed nothing in your hands. The
    archetype also lists the model in its resource list (the files loaded with it), which still
    named the old model. Changing the model now updates it everywhere, and changing it again
    repairs weapons made with 1.6.0

1.6.0 - custom models
  - .obj -> .xbg: make a weapon (or any) model your own. Edit the game's model in Blender
    (move/scale/rotate vertices), export .obj, and FC4Hook writes your shape into the game's
    model, keeping its UVs, normals, skinning and materials. Checks the .obj really lines up
    with the model first and refuses (with the reason) if it doesn't
  - Workshop > Model: "Use my .obj" converts it and points the weapon at the new model in one
    click
  - F8 > Developer > Models: convert an .obj to replace a model everywhere in the game
  - tools\fc4mdl.exe: the same converter outside the game (drag the .xbg and .obj onto it)

1.5.2
  - Workshop: fire rate was shown (and would have been saved) as a huge number: the game
    stores it as a decimal despite its name. Ammo used per shot shows as a plain number
  - Workshop weapons are registered with the game automatically as the world loads (retries
    until the game's weapon table is ready), not only on the first Give

1.5.1
  - Fixed: "Give it to me" on a Workshop weapon crashed the game. A new weapon's properties
    archetype isn't loaded at startup like the game's own, and the game expects it to be.
    FC4Hook now loads every Workshop weapon's properties and pickup as soon as you're in the
    world, and any give (Workshop or Armory tab) waits until they're in.
  - Fixed: Workshop weapons couldn't be given and their pickups couldn't be taken. The game
    doesn't read a weapon's properties from the weapon itself: it looks them up in a table it
    builds at startup from entitylibraryNamesToResId.fcb, which only has the game's weapons.
    FC4Hook now adds every Workshop weapon to that table when you enter the world and before
    every give (Workshop tab shows "Game registration: ...")
  - Safety net: if the game is ever about to add a weapon whose properties aren't loaded, it's
    skipped with a warning in the log instead of crashing
  - F8 > Developer > Models: extract any .xbg model with its materials and textures (+ .dds
    copies) to dumps\extracted: type its path, give an archetype id (e.g. a weapon) to get every
    model it uses, or pick from the models the File log has seen. The Workshop's Model tab has
    an "Extract it" button for the weapon's current models

1.5.0 - Weapon Workshop
  - New F8 > Workshop tab: make a new weapon from any weapon in the game in one click. FC4Hook
    copies its item, properties and pickup archetypes into a new mod with new ids (links,
    internal paths and path hashes all rewritten), gives it a unique name, adds it to the
    Armory. No FCB converter needed
  - Stats editor: fire rate, magazine size, reload times, range, recoil, move speed, silent,
    infinite ammo and more, with the original weapon's value next to each one; or every
    value in the weapon, under the game's own field names
  - Model editor: point a weapon's first/third-person model at your own .xbg (or any model in
    the game); warns when the file isn't there yet
  - FC4Hook can now read the game's binary .fcb files itself and names their fields from
    FC64.dll (about 57,000 names), the base for more editors to come

1.4.4 - custom archetypes
  - Spawner: "Check an archetype (why won't it spawn?)". Type an id or check every archetype
    your mods add: shows where the file comes from and points out the usual mistakes in plain
    words: file not found / wrong name, still XML instead of binary .fcb, the id inside the
    file doesn't match its file name (copied archetypes), models/textures/materials it uses
    that don't exist, missing weapon properties or pickup archetype
  - Fixed: weapon pickups and archetype lookups only searched the game's own archives, so
    archetypes added by a mod were never found (custom weapons always spawned as a bare model)
  - mods\README.txt: step-by-step checklist for making a new archetype

1.4.3
  - Spawner: things spawn as soon as they've loaded. Each spawn now waits for its own archetype
    (checked every 0.1 s) instead of queueing behind a slow one, so no more pile-ups

1.4.2

1.4.1

1.2.0 - modding toolkit
  Loose-file mods
    - fc4hook\mods\<Mod>\files\... : put game files at their in-game path and the game loads
      them instead of its own; new paths work too (new archetypes, textures, animation
      packages). Packed automatically at startup into data_win32\fc4hook_loose.* (only when
      something changed) and mounted above all game archives. Load order via
      mods\load_order.txt, later mod wins; conflicts are logged
    - New Mods tab: every installed mod, with on/off switches
    - Gibbed __UNKNOWN\<hash>.ext files can be shipped as they are
    - Disabled mods' armory.txt entries are hidden too
  Developer tools
    - File log: records every file path the game asks for, with its file id (also in
      dumps\file_log.txt); path -> file id calculator
    - Resource log (in the File log): every resource the game creates, with its engine type
      ([CAnimationPackageResource], meshes, move data...), including ones it loads by id
      without a path; "Record from game start" to catch what loads with the world
    - "Label animation clips": tags every animation clip in the log with its length and the
      weapon / bone names stored inside it (e.g. {2.30s ak74m RightHand}), so you can find a
      gun's animations and swap them; also written to dumps\animation_clips.txt
    - Extract any logged file from the game's archives (LZO decompressed) to
      dumps\extracted\, and "swap test": make file A load game file B in one click
      (mods\FC4Hook_SwapTest)
    - Texture editing: extracting a texture also writes a .dds of the whole image (both
      .xbt halves joined); "Install edited textures" packs every edited .dds back into the
      game's format in mods\MyTextures. Your edited .dds is never overwritten by a re-extract
    - fc4hook\tools\fc4tex.exe: the same converter outside the game (drag .xbt / .dds onto it)
    - Spawner: spawn any archetype id in front of you with the game's own factory
      (weapons from the Armory list, props, vehicles, NPCs, your own archetypes); remove them
    - Animation: attach/detach animation packages, play / force-play animations by path on
      you or on what you spawned, StartPlayAnim/StopPlayAnim, show the current animation
    - Clip monitor (Animation tab): lists every animation clip the moment the game starts
      playing it (hooked at the Move graph's clip node), newest first, with its labels and
      Replace / With buttons for the swap tool
    - Animation state browser: 540 of the game's Move-graph states (holster, draw, takedowns,
      cover, swimming...) and animation packages, searchable, one click to play/attach;
      also picks up every new name your File log records
  Plugin API v3
    - HookVtable / UnhookVtable, OnPresent render callback with the game's D3D11 device,
      context and swapchain, FileId(path), QueueLua54, GetLooseStatus
    - MinHook is now initialised thread-safely
  Lua
    - Game Lua: ModFileId, ModArchetypeFile, ModLooseStatus, ModFileLog, FC4Spawn.*, FC4Anim.*
    - Lua 5.4: fc4.file_id, fc4.file_log, fc4.loose_status, mem.vtable
  Fixes
    - Attachments: guns whose attachment limit is used up (or 0, like the AK-47, Skorpion
      and M133) now take attachments too
    - Fly: "Freeze body" works straight away, also when switched on mid-flight, and is
      re-applied while flying. "Steady camera" was removed: the game function it used only
      blocks scripted camera changes, not the falling camera

1.0.0 - first public release
  Menu
    - New tab layout: Cheats, Armory, Travel, Co-op, Console, Settings, About
      (+ Developer when developer mode is on)
    - Error/warning counter at the top of the menu; click it to open the Console
    - Menu size setting, refreshed look
  Cheats
    - God mode, unlimited ammo, slow motion and time lock are now on/off switches that
      stay on through deaths, cutscenes and loads
    - "Remember switches" keeps them on after restarting the game
    - Slow motion speed slider, time of day sliders + presets
    - 5 saved teleport positions, "Unstick (up 30 m)"
    - Weather and world-unlock buttons; anything the game doesn't support is greyed out
    - Bell tower travel no longer turns your God mode switch off when you land
    - Optional hotkeys for god mode, unlimited ammo, refill, slow motion, Armory
  Armory
    - Every weapon in the game (73): all categories incl. signature weapons, with the
      game's real template ids, plus experimental throwables
    - Search, favourites, "Give whole category", queued gives, per-weapon result
    - Optional ammo refill after giving
    - Your own list in armory\custom.txt; mods add entries with mods\<Mod>\armory.txt
    - No custom weapons bundled any more
  Logger
    - Log levels (debug/info/warn/error) with millisecond timestamps
    - Previous session kept as fc4hook.prev.log
    - Crash reports in fc4hook\crashes\ (fault address as module+offset, registers,
      stack, loaded modules, last log lines)
    - Console: level filters, text filter, copy, clear, open folder, colours,
      Lua command history, "=expr" to print a value
    - Lua: ModLogDebug / ModLogWarn / ModLogError
    - Much quieter by default (diagnostic detail moved to the debug level; file-access
      tracing is now opt-in: [Debug] TraceFileAccess=1)
  Settings
    - fc4hook.ini is created with comments on first start; everything editable in game
  New cheats
    - Infinite magazine (never reload), no fall damage, speed boost (adjustable),
      fly (W/A/S/D, Space/Ctrl, Shift = fast) and noclip, launch up
    - Money (set/add), XP, skill points, costume switch (experimental)
    - Teleport to any outpost or safe house (list built from the world), and to the
      current objective
    - Fly: zero fall speed, steady camera (locks the falling camera/pose adjuster), optional
      frozen body, and Space/Ctrl are kept from the game (DirectInput filter) so they don't
      jump/deploy the wingsuit or crouch while flying
  Armory
    - Attachments: lists the attachments the gun in your hands actually supports (read
      from the gun itself), shows which are fitted, fits them with the game's own routine,
      and removes them all
  Lua 5.4
    - A stock Lua 5.4 runs alongside the game's Lua 5.1: 64-bit integers, game.* bridge
      (call any game function, handles for game objects), mem.* with plain integers,
      fc4.* (ticks, timers, events, keys, files, menu buttons). Scripts: fc4hook\lua\
    - Console can run Game Lua or Lua 5.4; Developer > Lua 5.4 tab
    - Game Lua gets ModKeyDown(vk)
  Memory binder
    - Read/write/scan game memory from Lua: Mem* functions + the Mem.* wrapper
      (typed reads/writes, strings, bytes, signature scan, RIP resolve, pointer chains,
      dumps, entity objects incl. Mem.player(), freeze, native call). Cheat Engine style
      address expressions like "[FC64+2DD8958]+8"; bad addresses return nil, no crash
    - Developer > Memory tab: live value viewer/writer, watch list with freeze, hex view
  Travel
    - Fixed: teleporting to a bell tower could re-teleport you every frame (delay, then
      stuck glitching, blocking fast travel/quitting). Now one teleport, waits until you
      arrive, re-drops only if you fall through, hard 30 s limit, else sends you back
    - Cancel travel button
  Scripting / plugins
