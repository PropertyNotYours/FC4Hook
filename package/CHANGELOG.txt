FC4Hook changelog
=================

1.6.0 - custom models
  - .obj -> .xbg: make a weapon (or any) model your own. Edit the game's model in Blender
    (move/scale/rotate vertices), export .obj, and FC4Hook writes your shape into the game's
    model, keeping its UVs, normals, skinning and materials. Checks the .obj really lines up
    with the model first and refuses (with the reason) if it doesn't
  - Workshop > Model: "Use my .obj" converts it and points the weapon at the new model in one
    click
  - F8 > Developer > Models: convert an .obj to replace a model everywhere in the game
  - tools\fc4mdl.exe: the same converter outside the game (drag the .xbg and .obj onto it)

1.5.2
  - Workshop: fire rate was shown (and would have been saved) as a huge number: the game
    stores it as a decimal despite its name. Ammo used per shot shows as a plain number
  - Workshop weapons are registered with the game automatically as the world loads (retries
    until the game's weapon table is ready), not only on the first Give

1.5.1
  - Fixed: "Give it to me" on a Workshop weapon crashed the game. A new weapon's properties
    archetype isn't loaded at startup like the game's own, and the game expects it to be.
    FC4Hook now loads every Workshop weapon's properties and pickup as soon as you're in the
    world, and any give (Workshop or Armory tab) waits until they're in.
  - Fixed: Workshop weapons couldn't be given and their pickups couldn't be taken. The game
    doesn't read a weapon's properties from the weapon itself: it looks them up in a table it
    builds at startup from entitylibraryNamesToResId.fcb, which only has the game's weapons.
    FC4Hook now adds every Workshop weapon to that table when you enter the world and before
    every give (Workshop tab shows "Game registration: ...")
  - Safety net: if the game is ever about to add a weapon whose properties aren't loaded, it's
    skipped with a warning in the log instead of crashing
  - F8 > Developer > Models: extract any .xbg model with its materials and textures (+ .dds
    copies) to dumps\extracted: type its path, give an archetype id (e.g. a weapon) to get every
    model it uses, or pick from the models the File log has seen. The Workshop's Model tab has
    an "Extract it" button for the weapon's current models

1.5.0 - Weapon Workshop
  - New F8 > Workshop tab: make a new weapon from any weapon in the game in one click. FC4Hook
    copies its item, properties and pickup archetypes into a new mod with new ids (links,
    internal paths and path hashes all rewritten), gives it a unique name, adds it to the
    Armory. No FCB converter needed
  - Stats editor: fire rate, magazine size, reload times, range, recoil, move speed, silent,
    infinite ammo and more, with the original weapon's value next to each one; or every
    value in the weapon, under the game's own field names
  - Model editor: point a weapon's first/third-person model at your own .xbg (or any model in
    the game); warns when the file isn't there yet
  - FC4Hook can now read the game's binary .fcb files itself and names their fields from
    FC64.dll (about 57,000 names), the base for more editors to come

1.4.4 - custom archetypes
  - Spawner: "Check an archetype (why won't it spawn?)". Type an id or check every archetype
    your mods add: shows where the file comes from and points out the usual mistakes in plain
    words: file not found / wrong name, still XML instead of binary .fcb, the id inside the
    file doesn't match its file name (copied archetypes), models/textures/materials it uses
    that don't exist, missing weapon properties or pickup archetype
  - Fixed: weapon pickups and archetype lookups only searched the game's own archives, so
    archetypes added by a mod were never found (custom weapons always spawned as a bare model)
  - mods\README.txt: step-by-step checklist for making a new archetype

1.4.3
  - Spawner: things spawn as soon as they've loaded. Each spawn now waits for its own archetype
    (checked every 0.1 s) instead of queueing behind a slow one, so no more pile-ups

1.4.2
  - Fixed: the menu went blank when opening the spawner's People / Animals / Vehicles list

1.4.1
  - Spawner is now its own tab, next to Travel (no developer mode needed)
  - Spawner catalog sorted into plain categories (People, Animals, Vehicles, Weapons,
    Pickups & collectibles, Props, Technical) with groups like Villagers, Predators & big
    game, Land / Water / Air, Weapon pickups, Furniture & clutter...; readable names; the
    search looks through every category; mission/multiplayer/test variants hidden unless you
    tick "variants"; "game names" shows the raw archetype paths
  - Fixed: catalog names had stray characters in front ("nCfcc_graphics", "n:fcc_vehicles"),
    which split one library into dozens. Old archetypes.txt files are cleaned when loaded

1.4.0 - spawner, slow-motion sound, fixes
  Spawner
    - Weapons spawn as real pickups you can walk up to and take (FC4Hook finds each weapon's
      pickup archetype in the game data). "Model only" still spawns the bare model
    - New "NPCs, animals, vehicles..." list: Build catalog once and FC4Hook lists every
      archetype in the game, by library, with a search box and a Spawn button
  Cheats
    - Slow motion now slows the sound too (option "Slow the sound too")
    - FOV: no more glitch when aiming. The override is held every frame, and while you aim
      (right mouse / left trigger) the game's own ironsight and scope zoom take over
    - Vehicle boost: higher top speed (the boost keeps its own target speed instead of being
      pulled back by the game every frame); the right trigger works as throttle
    - Teleport position slots read from positions.txt (thanks Seth)
  Lua (game scripts)
    - ModPadTrigger("left"|"right") -> 0..1, ModSetAudioSpeed(f), ModArchetypeRef(id, field)

1.3.1
  - FOV override stays on (the game kept resetting it)
  - Vehicle speed boost: hold W to accelerate faster

1.3.0 - quality of life + modder UI
  Cheats
    - FOV slider (past the game's menu limit) and a separate weapon FOV slider, using the
      game's own FOV override (aiming and cutscenes still work); applied again after loads
    - Hide HUD switch (+ hotkey)
    - Karma: shows your karma level and points, Give karma button
    - Vehicles: speed boost (faster acceleration up to a top speed you choose) and instant
      brake (+ hotkey)
    - Fixed (1.2.1): the Fly switch could be greyed out
  Mods tab
    - "Loose files in use": every loose file with the mod it comes from, search, "only
      conflicts", and which other mods shipped the same file but lost on load order;
      "Check against game files" shows whether each file replaces a game file or is new
  Gamepad
    - The F8 menu works with a controller: hold L3 + R3 for half a second to open/close it,
      D-pad / stick to move, A to press, B to go back. The game doesn't get the pad while
      the menu is open (Settings: GamepadMenu)
  Lua 5.4
    - fc4.ui: scripts make their own windows in FC4Hook's overlay (text, buttons, checkboxes,
      sliders, text boxes, combos, progress bars), plus overlay windows that stay on screen
      with the menu closed. See lua\README.txt and lua\examples\ui_demo.lua

1.2.1 - bug fixes
  - The game no longer gets keyboard and mouse input while the F8 menu is open (it reads
    both through DirectInput, so they went "through" the menu). Key and button releases still
    reach it, so nothing stays held when you close the menu
  - Fly / noclip: Shift (fast fly) no longer opens the wingsuit
  - Fly: no more low-gravity jumps after flying (fly doesn't change your gravity any more)
  - Attachments: fitting a suppressor no longer leaves the gun's firing sound looping

1.2.0 - modding toolkit
  Loose-file mods
    - fc4hook\mods\<Mod>\files\... : put game files at their in-game path and the game loads
      them instead of its own; new paths work too (new archetypes, textures, animation
      packages). Packed automatically at startup into data_win32\fc4hook_loose.* (only when
      something changed) and mounted above all game archives. Load order via
      mods\load_order.txt, later mod wins; conflicts are logged
    - New Mods tab: every installed mod, with on/off switches
    - Gibbed __UNKNOWN\<hash>.ext files can be shipped as they are
    - Disabled mods' armory.txt entries are hidden too
  Developer tools
    - File log: records every file path the game asks for, with its file id (also in
      dumps\file_log.txt); path -> file id calculator
    - Resource log (in the File log): every resource the game creates, with its engine type
      ([CAnimationPackageResource], meshes, move data...), including ones it loads by id
      without a path; "Record from game start" to catch what loads with the world
    - "Label animation clips": tags every animation clip in the log with its length and the
      weapon / bone names stored inside it (e.g. {2.30s ak74m RightHand}), so you can find a
      gun's animations and swap them; also written to dumps\animation_clips.txt
    - Extract any logged file from the game's archives (LZO decompressed) to
      dumps\extracted\, and "swap test": make file A load game file B in one click
      (mods\FC4Hook_SwapTest)
    - Texture editing: extracting a texture also writes a .dds of the whole image (both
      .xbt halves joined); "Install edited textures" packs every edited .dds back into the
      game's format in mods\MyTextures. Your edited .dds is never overwritten by a re-extract
    - fc4hook\tools\fc4tex.exe: the same converter outside the game (drag .xbt / .dds onto it)
    - Spawner: spawn any archetype id in front of you with the game's own factory
      (weapons from the Armory list, props, vehicles, NPCs, your own archetypes); remove them
    - Animation: attach/detach animation packages, play / force-play animations by path on
      you or on what you spawned, StartPlayAnim/StopPlayAnim, show the current animation
    - Clip monitor (Animation tab): lists every animation clip the moment the game starts
      playing it (hooked at the Move graph's clip node), newest first, with its labels and
      Replace / With buttons for the swap tool
    - Animation state browser: 540 of the game's Move-graph states (holster, draw, takedowns,
      cover, swimming...) and animation packages, searchable, one click to play/attach;
      also picks up every new name your File log records
  Plugin API v3
    - HookVtable / UnhookVtable, OnPresent render callback with the game's D3D11 device,
      context and swapchain, FileId(path), QueueLua54, GetLooseStatus
    - MinHook is now initialised thread-safely
  Lua
    - Game Lua: ModFileId, ModArchetypeFile, ModLooseStatus, ModFileLog, FC4Spawn.*, FC4Anim.*
    - Lua 5.4: fc4.file_id, fc4.file_log, fc4.loose_status, mem.vtable
  Fixes
    - Attachments: guns whose attachment limit is used up (or 0, like the AK-47, Skorpion
      and M133) now take attachments too
    - Fly: "Freeze body" works straight away, also when switched on mid-flight, and is
      re-applied while flying. "Steady camera" was removed: the game function it used only
      blocks scripted camera changes, not the falling camera

1.0.0 - first public release
  Menu
    - New tab layout: Cheats, Armory, Travel, Co-op, Console, Settings, About
      (+ Developer when developer mode is on)
    - Error/warning counter at the top of the menu; click it to open the Console
    - Menu size setting, refreshed look
  Cheats
    - God mode, unlimited ammo, slow motion and time lock are now on/off switches that
      stay on through deaths, cutscenes and loads
    - "Remember switches" keeps them on after restarting the game
    - Slow motion speed slider, time of day sliders + presets
    - 5 saved teleport positions, "Unstick (up 30 m)"
    - Weather and world-unlock buttons; anything the game doesn't support is greyed out
    - Bell tower travel no longer turns your God mode switch off when you land
    - Optional hotkeys for god mode, unlimited ammo, refill, slow motion, Armory
  Armory
    - Every weapon in the game (73): all categories incl. signature weapons, with the
      game's real template ids, plus experimental throwables
    - Search, favourites, "Give whole category", queued gives, per-weapon result
    - Optional ammo refill after giving
    - Your own list in armory\custom.txt; mods add entries with mods\<Mod>\armory.txt
    - No custom weapons bundled any more
  Logger
    - Log levels (debug/info/warn/error) with millisecond timestamps
    - Previous session kept as fc4hook.prev.log
    - Crash reports in fc4hook\crashes\ (fault address as module+offset, registers,
      stack, loaded modules, last log lines)
    - Console: level filters, text filter, copy, clear, open folder, colours,
      Lua command history, "=expr" to print a value
    - Lua: ModLogDebug / ModLogWarn / ModLogError
    - Much quieter by default (diagnostic detail moved to the debug level; file-access
      tracing is now opt-in: [Debug] TraceFileAccess=1)
  Settings
    - fc4hook.ini is created with comments on first start; everything editable in game
  New cheats
    - Infinite magazine (never reload), no fall damage, speed boost (adjustable),
      fly (W/A/S/D, Space/Ctrl, Shift = fast) and noclip, launch up
    - Money (set/add), XP, skill points, costume switch (experimental)
    - Teleport to any outpost or safe house (list built from the world), and to the
      current objective
    - Fly: zero fall speed, steady camera (locks the falling camera/pose adjuster), optional
      frozen body, and Space/Ctrl are kept from the game (DirectInput filter) so they don't
      jump/deploy the wingsuit or crouch while flying
  Armory
    - Attachments: lists the attachments the gun in your hands actually supports (read
      from the gun itself), shows which are fitted, fits them with the game's own routine,
      and removes them all
  Lua 5.4
    - A stock Lua 5.4 runs alongside the game's Lua 5.1: 64-bit integers, game.* bridge
      (call any game function, handles for game objects), mem.* with plain integers,
      fc4.* (ticks, timers, events, keys, files, menu buttons). Scripts: fc4hook\lua\
    - Console can run Game Lua or Lua 5.4; Developer > Lua 5.4 tab
    - Game Lua gets ModKeyDown(vk)
  Memory binder
    - Read/write/scan game memory from Lua: Mem* functions + the Mem.* wrapper
      (typed reads/writes, strings, bytes, signature scan, RIP resolve, pointer chains,
      dumps, entity objects incl. Mem.player(), freeze, native call). Cheat Engine style
      address expressions like "[FC64+2DD8958]+8"; bad addresses return nil, no crash
    - Developer > Memory tab: live value viewer/writer, watch list with freeze, hex view
  Travel
    - Fixed: teleporting to a bell tower could re-teleport you every frame (delay, then
      stuck glitching, blocking fast travel/quitting). Now one teleport, waits until you
      arrive, re-drops only if you fall through, hard 30 s limit, else sends you back
    - Cancel travel button
  Scripting / plugins
    - Lua: ModSetState / ModGetState, ModVersion, ModFileExists, shared FC4.* helpers,
      one shared tick dispatcher (FC4Ticks) that switches off a broken module instead
      of spamming errors
    - Plugin API v2: LogLevel, SetState/GetState, GetRootDir, VersionString
      (plugins should check  api->version >= FC4HOOK_API_VERSION)
  Removed
    - Research/extraction scripts tied to one game build, the armory test script and
      the bundled custom weapon

0.9.0 - private build (Lua bridge, overlay, co-op tower fix, tower travel, armory, mod archive)
